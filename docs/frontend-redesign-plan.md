# 「更子」前端页面重构方案

> 版本 v0.1（评审稿） · 2026-09-24
> 范围：`web/` 全部页面（Vue3 + TS + Vite + Tailwind + Element Plus）
> 目标：在**不改动任何功能逻辑**的前提下，解决当前界面"AI 模板感重、缺乏人性化"的问题，把产品从"通用 SaaS 仪表盘"重塑为"**一间会讲故事的短剧制片室**"。

---

## 0. 结论速览

| 维度 | 现状 | 目标 |
|---|---|---|
| 品牌气质 | 硅谷 AI 落地页模板（黑底、蓝紫渐变、DM Sans、三卡图标） | 中文短剧制片工具：纸墨质感 + 朱砂强调色 + 宋体标题，画面即主角 |
| 核心工作台 | 后台式表格 + 大表单 + 彩色按钮堆砌 | 剧本稿纸 / 角色档案卡 / **分镜卡片墙 + 渲染队列**（CapCut Video Studio 范式） |
| 状态反馈 | 转圈 + 百分比，空状态冰冷 | 生成节点四态（待办/生成中/完成/失败重试）、骨架屏、任务化文案、上下文操作条 |
| 色彩语义 | 蓝=主色但绿=主按钮、米黄=下载，无语义系统 | 品牌色只做一个主行动；绿仅表"完成"、红仅表"危险/品牌"、中性色承载次要操作 |
| 字体 | DM Sans（AI 工具默认字体，与中文内容气质冲突） | 标题 Noto Serif SC（思源宋体）+ 正文 Noto Sans SC；数字/英文保留几何无衬线 |
| 深色模式 | 纯黑 #000 + 高饱和色块刺眼 | 暖炭"放映厅"暗色（#181612 系），降低色块彩度，突出画面本身 |
| 响应式 | 无断点规范，小屏即坏 | 桌面优先（1440 基准），定义 5 档断点，≥1024 完整可用，平板/手机分级降级 |
| 预估工作量 | — | 设计 10 人日 + 前端 22 人日 + 联调测试 5 人日 ≈ **约 6 周（1 前端 + 0.5 设计）** |

## 1. 现状审计

审计方式：通读设计 token（[main.css](../web/src/assets/styles/main.css)）与全部 8 个路由页面代码，实地运行并截图 10 张（浅色/深色）。

### 1.1 页面清单与角色

| 路由 | 页面 | 核心用户任务 |
|---|---|---|
| `/` | Dashboard | 了解产品、进入创作、查看最近作品 |
| `/dramas` | 作品列表 | 找到/新建一部剧 |
| `/dramas/create` | 新建作品 | 录入剧名、风格、描述 |
| `/dramas/:id` | 项目管理（5 Tab） | 概览统计、章节/角色/场景/道具 CRUD |
| `/dramas/:id/episode/:n` | **三阶段制作工作台** | 剧本→图片→分镜视频（产品心脏） |
| `/dramas/:id/settings` | 剧集设置 | 元数据编辑 |
| `/settings/ai-config` | AI 服务配置 | 文本/图片/视频模型与密钥管理 |

### 1.2 确诊的"AI 感"来源（按严重度排序）

**P0 —— 品牌层面的"千篇一律"**

1. **首页是 AI 落地页公式的标准答案**：纯黑首屏 + 白色超大字 + **蓝紫渐变标题文字**（`--accent-gradient: #007aff→#5856d6`）+ "AI 驱动 · 一键生成"胶囊 + 三栏圆圈图标 features + "四步完成创作" + "准备好开始创作了吗？" CTA。行业研究证实这正是 2025–2026 被称为 "AI slop design" 的统计中位数外观（见 §2.3），任何 AI 建站工具的默认产物都长这样。
2. **视觉语言与产品内容零关联**：产品承载的是中文网文/短剧（古风玄幻、都市逆袭），界面却是英文 SaaS 审美——DM Sans、Apple 蓝、通用圆角卡。用户看不到"剧"的味道。
3. **作品封面全部是同一张蓝色渐变占位图 + 摄像机图标**，6 部作品无法视觉区分。系统里明明已经存有大量生成的角色图/场景图，却没有用作封面。

**P1 —— 工作台像"后台管理系统"而非"影像生产工具"**

4. **分镜页是纯文字大表格**：20+ 行 × 8 列，无任何画面缩略图（镜头的图/视频已经生成了却看不到），行高松垮；每行重复塞蓝/绿/米黄三个彩色按钮。这与用户心智中的"分镜"（画面序列）完全相悖。
5. **剧本页是一个占满屏的 `<textarea>`**，像数据录入表单，不像创作工具；无字数、无段落结构、提取结果与原文无联动。
6. **工程语言泄漏到 UI**：角色标签直接显示英文枚举 `main` / `supporting`；"暂无描述""暂无数据"等占位文案冰冷。
7. **管理页是模板仪表盘**：蓝/绿/橙/黑四色统计卡 + 描述列表表格，数字是唯一信息。

**P2 —— 系统性与体验细节**

8. **色彩没有语义系统**：同屏出现蓝色（步骤条、编辑、批量生成）、绿色（"下一步""生成视频"主按钮）、米黄色（下载按钮）。`--success` 绿被劫持为品牌主 CTA，真正的成功状态反而无表达。
9. **反馈弱**：长任务只有转圈/百分比，不知道"正在生成谁、第几个、还要多久、失败了怎么办"；已有的 `taskProgress/taskMessage` 数据没有被好好可视化。
10. **深色模式 = 纯黑 + 高饱和**：#000 底 + 原彩度蓝绿按钮，对比生硬、彩色块刺眼，不符合长时间创作场景。
11. **无响应式规范**：表格和三阶段布局在 <1280px 即拥挤，移动端不可用。
12. **微交互缺失**：卡片 hover、选中、阶段切换均无过渡或很生硬；批量勾选后顶部操作条常驻，与"选中了什么"无空间关联。

### 1.3 值得保留的资产（重构不动）

- 完整、分层清晰的 token 变量体系（颜色/阴影/圆角/间距/过渡已具规模），重构以**换值 + 增补**为主，不必推倒。
- 深浅双主题、i18n（中/英）骨架、Element Plus 深色覆盖基础。
- 刚完成拆分的工作台组件结构（ScriptStep / ImageStep / StoryboardStep + composables），**恰好等于本次的三个改造单元**，职责边界清晰。
- 已有通用组件：BaseCard、EmptyState、StatCard、ActionButton、SlidePanel、ImagePreview，可在其上扩展而非新造。

## 2. 标杆研究（2025–2026）

### 2.1 直接对标：CapCut Video Studio（剪映网页新版，2026）

与更子的流程**几乎完全同构**：剧本 AI → 分镜 → 图/视频生成 → 精修。其两个关键设计决策直接可借鉴：

- **去时间线，改"可视化画布 + 分镜卡片"**：脚本自动解析为一张张 **shot card，每张卡就是一个独立生成节点**，可在卡上就地改 prompt、挂参考图、单独重生成，而不是在表格行/时间线轨道里操作。
- **先看板后成片**：分镜阶段允许在生成任何一帧视频前，通过拖排卡片调整叙事节奏。
- 视觉：克制的深色工作室基调，画面缩略图是界面绝对主角，控件退居次要。

### 2.2 光谱两端：Runway 与 Pika

- **Runway（专业端）**：打开就是编辑器——资产 bin、模型选择器、时间线、多轨精修；暗色"剪辑室"氛围；角色一致性通过"参考图系统"组织。给我们的启发：**专业工具感来自"资产与流程可见"，不是来自更多按钮**。
- **Pika（轻量端）**：一个输入框 30 秒出片，极简、快速迭代。给我们的启发：每个阶段的**主动作应当唯一且醒目**，其余操作降噪。

辅助参考：Frame.io（帧级审核的批注/状态流）、Boords / Storyboarder（分镜卡编号、景别标签体系）、Linear（克制配色、状态徽章、键盘流与微交互质感）、Craft/Notion（编辑式排版与空状态文案）。

### 2.3 "AI 感"为什么发生：行业证据

- 2026 年行业分析将 AI 生成站点的统一样貌命名为 **AI slop / median aesthetic**：Inter 类字体、indigo→purple 渐变 hero、深底白字、三圆角卡、sparkle 图标、三步说明区。其成因是统计性的——模型输出训练集的中位数，而非做出选择。Tailwind 作者公开调侃过 indigo 默认色"导致了地球上所有 AI UI 都是靛蓝色"。
- 数据：约 60% 的新 AI 产品站首两屏出现紫色；80%+ AI 建站工具默认 Inter。**这些元素单独看都不丑，问题是"它们不是选择"，因此让产品不可记忆。**
- 2026 反向趋势：有机/反网格布局、**字体成为主角（display + body 配对）**、暖色与自然色板（Pantone 2026 年度色 Cloud Dancer 及大地中性色）、有功能意义的微动效、编辑式/杂志化排版、"humanity 与 authenticity 是货币"。

**对更子的含义**：我们不需要追新怪风格，而是要做出一个**从产品内容长出来的、有明确观点的选择**——短剧、中文、片场、稿纸、分镜、放映厅。

## 3. 设计风格定位

### 3.1 一句话概念

> **「短剧制片室」**——纸白与墨黑的稿纸底色、宋体的戏剧性标题、朱砂红的"开拍"行动色；界面退到幕后，让用户生成的每一帧画面成为主角。

### 3.2 五条风格原则

1. **画面优先（Footage First）**：凡有图/视频的地方，缩略图必须是卡片的主体；控件与文字围绕画面排布，而不是把图塞进表格角落。
2. **编辑部排版（Editorial）**：用宋体大标题、明确的字号阶梯、留白节奏建立"这是一部作品"的郑重感；禁止用渐变色块和图标圆圈制造廉价的"科技感"。
3. **一个行动色（One Action）**：每个视图只有一个主行动（朱砂红），完成是绿、危险是红、其余全部中性化。
4. **状态可扫读（Scannable States）**：生成进度、成功失败在 1 秒内可从缩略图上的角标/遮罩读出，不需要读文字。
5. **静而不冷（Warm & Quiet）**：暖纸/暖炭底色、克制动效、像工具不像广告牌；把"AI 驱动·一键生成"这类自夸文案全部删除。

### 3.3 色彩方向（token 建议值）

**主推：纸墨 + 朱砂（与中文短剧内容强关联）**

| token | 浅色 | 深色（暖炭放映厅） | 用途 |
|---|---|---|---|
| `--bg-primary` | `#F7F4EE` 暖纸 | `#171512` 暖炭 | 页面底 |
| `--bg-card` | `#FFFDF9` | `#201D18` | 卡片/表面 |
| `--bg-inset` | `#F1EDE4` | `#151310` | 嵌入区/代码/文本域 |
| `--text-primary` | `#221E18` 墨 | `#F2EDE4` | 主文字 |
| `--text-secondary` | `#6F675B` | `#A79E8F` | 次要文字 |
| `--border-primary` | `#E4DDCE` | `#322D25` | 分隔线 |
| **`--accent`（朱砂）** | **`#C0392B`** | `#D65542` | 唯一主行动/品牌时刻 |
| `--accent-soft` | `#F7E7E2` | `rgba(214,85,66,.16)` | 选中底/徽章底 |
| 铜金（品牌点缀） | `#A9803E` | `#C9A45F` | 仅用于品牌标识、集数字号等极少处 |
| `--success` | `#2F7D52` | `#4E9C73` | **只**表示完成/成功 |
| `--warning` | `#B9791F` | `#D39A45` | 等待/处理中 |
| `--danger` | `#B23B3B` | `#D65A50` | 删除/失败 |
| `--info` | `#4A6B8A` | `#6E93B5` | 提示信息 |

- 删除 `--accent-gradient`（蓝紫渐变）与 hero-gradient 的一切用法；品牌渐变最多保留一条"朱砂→赭石"极淡渐变用于 Logo/空状态插画，不用于文字。
- Element Plus 主色覆盖变量（`--el-color-primary` 等）整体切到朱砂系，按钮/分页/开关自动跟随。

**备选 B：靛青夜场（冷调）**：主色 `#3D5A80` 靛蓝 + 冷纸白 `#F5F6F4`，气质接近 Frame.io / Linear，更"现代专业工具"，但与中文内容的关联弱、辨识度低。**建议主推 A**，B 作为用户评审时的备选。

### 3.4 字体

- **标题/品牌/数字大字**：Noto Serif SC（思源宋体）700，用于：Logo"更子"、页面 H1/H2、分镜编号、集数。
- **正文/UI**：Noto Sans SC（思源黑体）400/500/600。
- 英文与数字辅助：正文沿用系统 SF/Segoe 或继续 DM Sans 仅用于拉丁字符（`font-family` 按脚本回退即可，无需全站换字）。
- 中文宋体体积大，落地策略：**只加载 600/700 两个字重**，走字体服务的 unicode-range 动态分包或 `font-display: swap`；仅标题用宋体，整体增量可控制在首屏可接受范围（实测国内 CDN 思源宋体单字重分包后首屏约 30–80KB）。
- 字阶（桌面基准）：H1 32/40 serif、H2 22/32、H3 17/26、正文 14/22、辅助 12/18；行高比正文 1.6–1.7（中文长文本需要更大行距，这是当前 textarea 阅读感差的原因之一）。

### 3.5 质感与形状

- 圆角收敛：卡片 12px（现 12–24px 偏软偏"萌"），按钮 8px，徽章 6px/full；阴影减淡，改用**1px 暖边框 + 极轻阴影**表达层级（编辑物质感而非玻璃悬浮）。
- 禁止：毛玻璃滥用、发光阴影（glow）、渐变文字、彩色图标圆圈底。
- 图标：统一 Element 线性图标 + 1.5px 描边感；空状态用极简线稿（场记板、胶片孔、稿纸）而非插画大礼包。

## 4. 用户体验优化策略

### 4.1 信息架构

- **全局**：顶栏保留（品牌 + 主导航 + 创建 + 主题），但降低自身视觉重量（去毛玻璃白光带，改纯色 + 1px 底线）。
- **工作台**：新增一条**上下文条**（剧名 · 第 N 集 · 自动保存状态 · 制作进度 3/4 阶段），让用户随时知道"我在哪、东西存了没"；步骤条由"胶囊填充"改为"编号轴 + 已完成打勾"，点击可回跳已完成阶段。
- 阶段 2 分镜页采用**双区布局**：主区=分镜卡片墙；右侧（或底部抽屉）=**渲染队列**，集中展示批量生成任务。

### 4.2 生成任务的统一状态模型（核心 UX 改进）

所有"生成"对象（角色图、场景图、每个镜头视频）统一四态：

| 状态 | 卡片表达 | 操作 |
|---|---|---|
| 待生成 | 虚线边框占位 + 线稿图标 + "待生成" | 立即生成 |
| 生成中 | 缩略图位骨架/shimmer + 角标进度环 + "正在塑造·贾富 3/5" | 可取消（如接口支持） |
| 已完成 | 真实缩略图 + 绿色小勾角标 | 预览/重生成/下载 |
| 失败 | 缩略图位暖色警示底 + 失败原因短句 | **重试** / 改提示词 |

配套：
- 顶部/右侧渲染队列汇总总进度、剩余数量、失败数；完成一次轻提示音 + 静默 toast（可选开关）。
- 文案任务化：把"加载中"换成"正在把第 14 镜写成画面…"；错误文案说人话（后端 JSON 截断类错误显示"模型这次没说完整，已自动重试 1/3"，配合后端未来的重试机制）。

### 4.3 空状态 / 首访引导

- 空状态必须包含：一句具体处境描述 + 一个主行动按钮 + 一幅克制线稿。示例：分镜页空状态——"这一集还没有分镜。先在「章节内容」里粘贴剧本，拆分会把它排成镜头卡片。"（按钮：去拆分）。
- 新用户首访工作台：步骤条上做一次轻量气泡指引（3 步，可跳过，不做遮罩式 onboarding 弹窗）。
- 作品列表空状态：从"暂无数据"改为"你的第一部剧，从一句话梗概开始"+ 新建按钮。

### 4.4 文案（UX Writing）

- 删除自夸："AI 驱动·一键生成""强大功能，简单操作""准备好开始创作了吗？""释放无限想象"。
- 枚举中文化：`main→主角`、`supporting→配角`，其余角色类型映射为"群演/旁白"等；风格标签同理。
- 按钮以动词开头说结果："保存剧本""重选 2 张""生成这 3 个镜头"；危险操作二次确认说明后果（"删除后该角色的分镜引用将一并失效"）。
- 全部新增文案同步进 `zh-CN.ts / en-US.ts`。

### 4.5 无障碍（底线，不额外炫技）

- 正文/背景对比度 ≥ WCAG AA（4.5:1），当前浅色灰字 `#aeaeb2` 在白底仅 2.6:1，需加深。
- 所有交互元素键盘可达，焦点环使用统一 2px 朱砂/中性 outline；图标按钮提供 aria-label。
- 动效全部包 `@media (prefers-reduced-motion: reduce)` 降级。

## 5. 交互模式改进建议

1. **上下文操作条（Contextual Action Bar）**：角色/场景/镜头勾选后，屏幕底部浮现一条悬浮操作条（"已选 3 个角色 · 批量生成 · 加入素材库 · 删除"），替代当前常驻顶部的批量区；未选中时不占位。
2. **分镜卡片墙**：`auto-fill minmax(220px, 1fr)` 响应网格；每张卡：画面（16:9）+ 顶部编号/景别·运镜徽章 + 底部标题与状态 + hover 浮现行内操作（编辑/生成/下载收进一个"更多"菜单，不再三彩色按钮平铺）。提供"卡片墙 / 紧凑表格"视图切换（表格留给高级用户批量核对）。
3. **卡片拖排（可选二期）**：长按拖拽调整镜头顺序——CapCut 的核心价值之一；一期可先不做，仅在卡片右上预留抓手位。
4. **就地编辑**：镜头标题/提示词在卡片上点击即改（Popover 或展开半幅抽屉），不用全屏 dialog 堆叠。
5. **阶段切换过渡**：200ms 内容淡入 + 8px 纵向位移，步骤轴平滑滑动；用 v-show 现状保留（避免轮询中断）。
6. **图片页 Hover 速览**：悬停角色卡显示大图与提示词摘要；点击进灯箱（已有 ImagePreview，复用）。
7. **乐观更新与防误操作**：保存中禁用提交、保存成功仅在上下文条闪"已保存 · 12:03"；删除走 Popconfirm 红字。
8. **键盘流**：`⌘/Ctrl + S` 手动保存（已有自动保存则提示"已自动保存"）；`←/→` 在三阶段间跳转；`Esc` 关弹窗。
9. **微交互预算**：时长只用 120/180/240ms 三档，缓动统一 `cubic-bezier(.2,.7,.3,1)`；仅用于 hover、选中、进出场、进度，不做装饰循环动画。

## 6. 响应式设计规范

产品是重工作台，策略明确为**桌面优先、移动端只保证浏览与轻操作**。

| 断点 | 宽度 | 布局行为 |
|---|---|---|
| XL | ≥1600 | 工作台最大内容宽 1440 居中；分镜墙每行 5–6 卡；渲染队列固定右侧栏 |
| L（基准） | 1280–1599 | 每行 4 卡；渲染队列改底部抽屉；首页正常多栏 |
| M | 1024–1279 | 每行 3 卡；管理页统计卡 2×2；表格出横向滚动（贴边阴影提示） |
| S（平板） | 768–1023 | 每行 2 卡；顶栏导航折叠为图标；三阶段步骤条可横向滑动；剧本双栏改单栏 |
| XS（手机） | <768 | 每行 1 卡；列表/概览/剧本阅读可用；图片与视频生成任务可提交、状态可查看，复杂编辑（分镜表、配置表单）提供"请在桌面端使用"的友好提示页而非直接坏掉 |

细则：
- 触控目标 ≥40×40px；移动端底部操作条贴底安全区（`env(safe-area-inset-bottom)`）。
- 字体用 clamp 流式缩放：H1 `clamp(24px, 2.4vw, 32px)`。
- 所有网格用 CSS Grid `auto-fit/auto-fill`，禁止写死卡片宽度的 flex 换行。
- 图片一律 `loading="lazy"` + 现有 `getImageUrl/hasImage` 逻辑；缩略图走后端已有尺寸或前端固定宽高比裁切，避免布局抖动。

## 8. 技术实现路径

### 8.1 技术栈与原则

- **不换栈、不加新依赖**（字体按需除外）：Vue 3.4+ / TS / Vite / Tailwind / Element Plus。
- 延续既定的组件拆分纪律：容器管状态，展示组件 props/emits/defineModel；每个改造单元独立构建验证（`cd web && npm run build`，以编辑器 0 error 为准）。
- **视觉改造与功能开发严格分离**：本次不改任何业务逻辑、API、store；后端仅需确认"作品封面可取的图片字段"这一个数据点。

### 8.2 三层落地

**第 1 层：Token 与基础（先做，全站自动跟 70%）**
- 重写 [main.css](../web/src/assets/styles/main.css) 的 `:root`/`.dark` 变量值（§3.3），增补：字体族变量、表面层级（inset/overlay）、语义状态色、字号行高变量、动效三档。
- 新增字体加载（index.html 或 `@font-face` + 按需分包）。
- Element Plus 覆盖文件（[element/index.scss](../web/src/assets/styles/element/index.scss)）切换主色系；统一 el-button 类型映射：**主行动 `primary`（朱砂），下载/编辑全部 `default` 文本按钮，完成态只用 badge 不用绿按钮**。

**第 2 层：新增/升级通用组件**（`components/common/`）
- 新增：`GenerationStatusBadge`（四态）、`ProgressRing`、`RenderQueue`（渲染队列抽屉）、`ContextBar`（工作台上下文条）、`StepAxis`（步骤轴）、`EntityCard`（角色/场景档案卡基类）、`ShotCard`（分镜卡）、`Skeleton*`、`EmptyState` 升级（已有组件，加插图槽与行动 slot）、`FilterBar`/`SegmentedControl`（视图切换）。
- 复用现有：BaseCard、SlidePanel、ImagePreview、ActionButton、PageHeader。
- 通用组件 props 设计先行，避免三个 Step 各写一套。

**第 3 层：页面装配**：按 §7 顺序 P10→P4→P3→P2→P1→P5→P6→P7→P8/P9（先地基与框架，再啃最重的分镜，营销与列表放后段，便于尽早在真实数据上验证方向）。

### 8.3 风险与对策

| 风险 | 对策 |
|---|---|
| Element Plus 表格/对话框深度样式覆盖成本高 | 分镜墙用自研卡片网格，el-table 仅保留紧凑视图与管理页，覆盖范围收窄；对话框统一走 SlidePanel/el-dialog 变量继承 |
| 思源宋体拖慢首屏 | 仅两个字重、unicode-range 分包、`swap`；先用系统宋体（`Songti SC`）做渐进回退，字体加载完自动替换，无 FOIT |
| 老用户习惯被打破 | 功能位置与流程一步不少；提供表格/卡片双视图；上线首周保留"切回紧凑视图"提示 |
| 朱砂红色在大量 CTA 场景显躁 | 一页一主按钮规则 + 大面积用 soft 底；成功绿克制使用 |
| 中英文 i18n 下排版错位 | 字阶与组件宽度按中英双语文案走查；宋体仅用于中文标题，英文标题回落 serif 西文栈 |
| 构建产物体积 | 不引入图标/动画库；新组件 tree-shake 友好；改造后对比构建产物大小 |

## 13. 最终决策修订（2026-09-24 拍板）

> **决策：采用方案 C —— 赛博终端 / CRT 霓虹方向全套落地**（依据用户提供的 Variant 六视图设计稿：首页 Hero、作品存档、生成终端、编辑器、系统配置、初始化会话）。A 纸墨朱砂静态稿仅作过程稿保留，不再实施。用户明确要求**完整 Three.js**，不接受轻量替代。

### 13.1 对第 3 章的替代：赛博设计规格

- **色板**：背景纯黑 `#000000` / 面板 `#0A0A0B`；文字 `#F5F5F7` / 次级 `#8A8A92` / 弱 `#55555C`；**信号红 `#FF0000` 为唯一品牌强调色**（激活态、进度、已完成、主 CTA）；终端绿 `#3DDC84` 仅用于成功日志/在线状态；琥珀 `#FFB020` 仅用于警告日志；青 `#00F0FF` 仅允许极少量故障点缀，不得成为功能色。
- **字体**：英文标签/编号/技术参数使用 JetBrains Mono（已以 `@fontsource/jetbrains-mono` 本地化引入，移除 Google Fonts 外链）；中文标题使用系统粗黑体（PingFang SC / HarmonyOS Sans / 雅黑，字重 800+）；正文保持系统无衬线。**标签统一"中文 + 全大写英文"混排**（作品存档 / WORKS ARCHIVE）。
- **形状**：圆角收敛到 2–4px；卡片/按钮以 1px 细描边表达层级，弃用 Apple 式大柔和阴影；红色仅作激活描边与细线。
- **全局氛围**：Three.js 线框多面体 + 粒子星空（全站共享同一实例，路由切换不销毁、无视觉差）；CRT 扫描线、暗角、四角取景框、十字准星光标固定于全站之上。
- **主题机制**：沿用现有 `.dark` class 双主题，语义改为"CRT_红色（深色，默认）/ 空白_白色（浅色全局翻转）"，信号红在两套中保持不变。

### 13.2 两条硬约束（助理保留、用户未反对）

1. **剔除一切假遥测**：设计稿中的 GPU 占用率、温度、FPS、码率、BUFFER、ENCODER 等无真实数据来源的 HUD 一律不做。界面只呈现可溯源数据（作品/图片/视频数量、会话存活时间、当前时间、真实任务进度与日志）。
2. **长文可读性例外**：剧本、分镜描述、对话等大段中文阅读区使用常规无衬中文字体与正常行高，不用等宽字体排中文、不压字距。

### 13.3 对排期与验收的修订

- 工作量在原估算上 **+8~10 人日**：Three.js 背景组件（含降级/dispose/分包）、CRT 全局层、全站组件 HUD 化皮肤。
- 新增验收项：`prefers-reduced-motion` 下 Three.js 停转、<768px 不启动 WebGL、切页背景实例不重建、three 独立分包且首屏不阻塞、HUD 无任何编造数据。
- 实施顺序：W1 token/字体/全局背景/CRT/外壳/首页 → W2 生成终端（对接真实轮询日志）→ W3 作品存档 + 分镜 shot card 墙 → W4 编辑器时间线 → W5 系统配置/新建会话 → W6 移动端与收尾。
